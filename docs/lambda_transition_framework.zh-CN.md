# λ 过渡训练框架设计（融合经典范式 + 公理库底座）

> English version: **[lambda_transition_framework.md](lambda_transition_framework.md)**

> **工具目录说明（2026-09-28）**：本文提到的历史研究脚本（`full_finetune.py`、
> `train_moe.py`、`train_moe_qat.py`、`train_lambda.py` 等）已归档到
> **`tools/legacy/`**；当前主线工具仍位于 `tools/`。工具总览见 `tools/README.md`。

> 目标：不脱离经典训练范式，而是**以经典范式为主干**，用公理库「叠加态 + λ 过渡参数」
> 作为**结构与精度变换的辅助机制**，解决经典范式未覆盖的「稀疏化」与「量化」两大变换。
>
> 核心原则：**验证可行性优先**。每个技术点先跑最小验证实验，硬数据 pass/fail，通过才深入。
>
> 关键修正（相对早期版本）：损失层面不做 λ 过渡——经典纯 CE 就是正解，λ 只作用于
> 结构稀疏化与量化这两个经典范式不覆盖的变换。
>
> 关键修正 2（2026-09-26）：结构稀疏化也不能走「dense 旁路 + λ_s 平滑过渡」——
> dense 兜底会稀释 CE 分化压力，导致 router 永远不分化（四轮实测坐实）。正确路径是
> **无兜底的全量训练 MoE**（λ 只做 router 内部 soft→hard 梯度退火，不做结构过渡）。

## 1. 前几轮失败的重新归因

硬数据：

| 实验 | validation ppl | 旧归因 | **新归因（修正）** |
|---|---|---|---|
| teacher | 21.53 | — | 基准 |
| 复用 attention + 从零训 FFN（KD α=0.9） | 77.38 | 损失固定 | **setup 错误：只训 FFN、冻结 attention** |
| 复用 attention + 从零训 FFN（纯 CE α=0） | 1711.07 | 损失硬切 | **同上：FFN 只能记忆，过拟合** |
| MoE λ 退火路由 | 成功分化 | — | 唯一正确的平滑过渡 |

**关键修正**：前几轮失败不是"损失函数选错"（CE/KD 之争是伪问题），而是**训练 setup 错误**——
冻结 attention、只训 FFN，导致 10M 参数的 FFN 要么记忆（过拟合 ppl1711）要么学不到
（能力不足 ppl77）。

**正确主干 = 经典全量训练范式**：所有参数可训练 + 纯 CE + AdamW + cosine LR。
这是千锤百炼的正道，正在后台跑的 `full_finetune.py` 就是它。

**λ 过渡的正确位置**：经典范式负责「学会语言建模」，λ 过渡负责「结构与精度的平滑变换」
——这是经典范式天然不覆盖、但我们的目标（MoE 稀疏 + q4 量化）必须做的两步。

## 2. 公理库数学底座（用于结构/量化变换，不用于损失）

### 支柱一：叠加态
`S_0(1,1) = {2,3}`：一个对象同时处于多个基态，携带多套信息，不矛盾（SHS-2）。

### 支柱二：λ 过渡参数（SHS-T + SHS-3）
`M(λ) = (1-λ)·A_classic ⊕ λ·B_new`，λ∈[0,1]。λ=0 经典基态，λ=1 新基态。
**SHS-3 硬约束：必须连续过渡，硬切换会失败。**

### 支柱三：Bregman 散度
CE/KL/MSE 均为其特例。可选，用于度量过渡路径平滑度。

## 3. 融合框架总览：经典范式主干 + λ 变换辅助

```
主干（经典范式，负责「学会」）：
  全量训练 + 纯 CE + AdamW + cosine LR + teacher 初始化 warm start
  （teacher 初始化替代 KD 蒸馏，复用 teacher 知识，无需软标签损失）

λ 变换（辅助，负责「变换」，叠加在主干之后）：
  结构 λ_s：  FFN = (1-λ_s)·稠密 ⊕ λ_s·MoE稀疏    λ_s: 0 → 1
  量化 λ_q：  权重 = (1-λ_q)·fp32  ⊕ λ_q·q4感知     λ_q: 0 → 1
```

完整训练路径：

```
阶段 0（经典预训练，纯 CE，全量）：teacher 初始化 → 全量训练至收敛
        ↑ 标准做法，负责把模型真正训练好（正在后台跑 full_finetune.py）
阶段 1（λ_s 结构稀疏化）：经典收敛点 → FFN 稠密平滑过渡到 MoE，router 学会分工
        ↑ λ 过渡，保持 ppl 不崩的前提下获得稀疏激活的带宽收益
阶段 2（λ_q 量化感知）：结构确定后 → 权重 fp32 平滑过渡到 q4，QAT 保精度
        ↑ λ 过渡，训练中适配 q4，避免 PTQ 精度损失
```

**与历史失败的对照**：前几轮既没有用经典范式（只训 FFN），也没有用 λ 过渡（硬切换）。
融合方案要求：**经典范式做主干，λ 过渡只做结构/量化变换**，二者各司其职。

## 4. 技术点分解（含假设 + 验证方案 + 判定标准 + 实现描述）

> 按可行性验证优先级排序。技术点 0 是总闸（经典主干），不通则整个方向无意义。

### 技术点 0：经典全量预训练基线【优先级：最高 / 总闸】

**假设**：全量训练（teacher 初始化 + 纯 CE）能突破 ppl 77 天花板，逼近 teacher 21。
这是经典范式，理论上必通；若不通，说明数据/模型规模有硬伤，止损。

**验证方案**：`full_finetune.py`（后台运行中）——teacher 初始化、全量可训练、纯 CE、
AdamW + cosine，1 epoch，每 5000 步测 validation ppl。

**判定标准**：
- ✅ PASS：validation ppl 明显低于 77，且持续下降趋势；
- ❌ FAIL：ppl 停滞在 77+，说明"从零/微调 32M 模型"在当前数据下有硬约束，止损。

**实现描述**：已完成（`full_finetune.py`），无新增工作。

---

### 技术点 1：λ_s 结构稀疏化（稠密 FFN → MoE）【优先级：高 / 已 FAIL 止损】

**假设**：经典预训练收敛后，用 λ_s 平滑过渡把稠密 FFN 稀疏化到 MoE，router 能在
「不崩 ppl」的前提下学会分工（这是经典范式不覆盖的变换，必须用 λ 过渡而非硬切）。

**验证方案**：在技术点 0 的收敛模型上叠加结构退火：
- 每层 FFN：`out = (1-λ_s)·dense_ffn(h) ⊕ λ_s·moe_ffn(h)`；
- λ_s 从 0 平滑退火到 1，观察 router 熵（分化）与 validation ppl 的协同变化；
- 对照组：直接硬切（λ_s 瞬间 0→1），对比 ppl 崩坏程度。

**判定标准**：
- ✅ PASS：λ_s→1 时 router 熵 < 1.8（分化）且 ppl 相对稠密基线上涨 < 20%；
- ❌ FAIL：router 不分化（熵≈log8）或 ppl 崩溃，止损。

**实测结果（2026-09-26）**：❌ FAIL，已止损。

四轮修正全部失败，硬数据：

| 版本 | 修正项 | λ_s→1 时 ppl | 涨幅 | L9 熵 | 判定 |
|---|---|---|---|---|---|
| v1 | λ_s 0→1（方向反） | 59.95 | +587% | 2.013 | ❌ |
| v2 | + λ_s floor + 独立 lr | 21.36 | +145% | 1.989 | ❌ |
| v4 | + aux_w=0 + 5000 步 | 15.84 | +81.5% | 1.965 | ❌ |
| ffn_e=256 | + 容量翻倍（0.47） | 13.67 | +56.7% | 1.950 | ❌ |

**根因（硬数据坐实）**：结构蒸馏存在**内在死结**——`dense 旁路兜底`（λ_s<1 时输出占主导）
把 CE 对 MoE 的梯度稀释成「微调残差」级别 → router 没有分化压力 → 8 专家看同样 token、
学同样残差、越来越同质 → router 更没理由分化（负反馈循环）。

四轮中 router 熵**始终**卡在 1.95~1.97（log8=2.079 均匀态），与容量（ffn_e 128/256）、
aux 开关、λ_s 方向**全部无关**。这证明「平滑过渡（dense 兜底保不崩）」与「router 分化」
在该架构下**互斥**——兜底越平滑，分化压力越弱。

**止损转向**：改走**全量训练 MoE**（`train_moe.py`），无 dense 兜底，纯 CE 直接驱动
router 分化。实测 router 熵成功降至 1.80，argmax match 0.607（接近稠密 teacher），
证明全量 MoE 是正路。详见技术点 1-b。

---

### 技术点 1-b：全量训练 MoE（无 dense 兜底）【替代技术点 1，已验证可行】

**假设**：不引入 dense 旁路，直接把每层 FFN 替换为 `LambdaMoE`（router + 8 专家），
复用 teacher 的 attention/embed/lm_head 权重 + MoE 旁路从零，全量训练 + 纯 CE。
无兜底时 CE 直接压 router 分化。

**实测结果（2026-09-26）**：✅ 可行。

- 配置：ffn_e=256, top_k=2, n_expert=8, 纯 CE, 5000 步；
- router 熵：1.968 → 1.80（真正分化，对比结构蒸馏恒卡 1.95~1.97）；
- 最终 argmax match = **0.607**（稠密 teacher 水平）；
- 可训练参数 41.77M，带宽收益 2.13x，容量比 0.47。

**ffn_e trade-off 扫描（2026-09-26）**：

| ffn_e | 容量比 | 带宽收益 | 参数量 | router 熵 | argmax match |
|---|---|---|---|---|---|
| **128** | 0.23 | **4.27x** | 32.18M | 1.80 | **0.641** |
| 256 | 0.47 | 2.13x | 41.77M | 1.80 | 0.607 |
| 384 | 0.70 | 1.42x | 51.35M | 1.80 | 0.581 |

**结论**：ffn_e=128 是 MCU 部署甜点——同时拿到最高质量（match 0.641）和最高带宽收益
（4.27x）。argmax match 随 ffn_e 增大反而下降，是 TinyStories 简单数据上容量过剩的
轻微过拟合。三个配置 router 均成功分化（熵 1.80），全量 MoE 路径稳定。

**实现描述**：`train_moe.py`，已从 KD 蒸馏改为纯 CE（`--loss ce`），并修复
StopIteration 单 epoch 退出 + flush + 周期 checkpoint。

---

### 技术点 2：λ_q 量化感知（fp32 → q4）【优先级：中 / 已判否，PTQ 足够】

**假设**：训练后量化（PTQ）精度损失大，λ_q 平滑过渡的量化感知训练（QAT）让模型在
训练中适配 q4，精度损失更小。

**验证方案**：技术点 1 通过后，训练末期引入 QAT：
- 权重 `W = (1-λ_q)·W_fp32 ⊕ λ_q·round(W_fp32/scale)·scale`（straight-through）；
- λ_q 从 0 平滑退火到 1，对比 PTQ（训练后直接量化）的 ppl 损失。

**判定标准**：
- ✅ PASS：QAT 的 q4 模型 ppl 明显优于 PTQ；
- ❌ FAIL：QAT 无增益或训练不稳定，退回 PTQ + 更保守位宽。

**实测结果（2026-09-26）**：❌ FAIL，QAT 无增益。

| 方案 | ppl | 相对 fp32 损失 |
|---|---|---|
| fp32 基线 | 12.73 | — |
| **PTQ（直接量化）** | **12.84** | **+0.9%** |
| QAT（λ_q 退火 2000 步） | 12.90 | +1.4% |

**结论**：QAT（+1.4%）不优于 PTQ（+0.9%），反而略差。PTQ 仅 +0.9% 几乎无损，说明
ffn_e=128 的 MoE 模型对 q4_0 天然鲁棒。QAT 的 straight-through 梯度噪声 + 对已收敛模型
的扰动大于收益。**技术点 2 判否，走 PTQ 即可**，省掉 QAT 复杂机制。

**实现描述**：`train_moe_qat.py`（fake-quant 与 convert_minueza 的 q4_0 规则位级一致，
用 `torch.nn.utils.parametrize` 实现 straight-through）。脚本保留作工具，但正式流程不再用。

---

### 技术点 3：teacher 初始化 vs KD 蒸馏的等价性验证【优先级：低 / 可选】

**假设**：teacher 权重初始化（warm start）已足够复用 teacher 知识，无需额外 KD 软标签
损失。即「初始化」等价于「蒸馏」，且更简单。

**验证方案**：技术点 0 基础上，对比「teacher 初始化 + 纯 CE」vs「随机初始化 + KD 蒸馏」，
看前者 ppl 是否已优于后者。

**判定标准**：
- ✅ PASS：teacher 初始化 + 纯 CE 已优于 KD 蒸馏，确认去掉 KD 损失是正确的；
- ❌ FAIL：KD 蒸馏有额外增益，重新引入。

**实现描述**：仅需一个对照训练脚本，无核心改动。

## 5. 分步骤落实计划（严格按序，每步有闸门）

| 步骤 | 内容 | 闸门（通过才进下一步） | 状态 |
|---|---|---|---|
| 0 | 经典全量预训练基线（`full_finetune.py`） | ppl < 77 | ✅ 完成（ppl 8.73） |
| 1 | 技术点 1：λ_s 结构稀疏化最小验证 | router 分化 + ppl 不崩 | ❌ FAIL 止损 |
| 1-b | 技术点 1-b：全量训练 MoE | router 分化 + 逼近稠密 | ✅ 可行（match 0.607） |
| 1-c | 扫 ffn_e ∈ {128,256,384} trade-off | 确定带宽收益上限 | ✅ 完成（ffn_e=128 甜点，4.27x） |
| 2 | 技术点 2：λ_q 量化感知最小验证 | QAT 优于 PTQ | ❌ 判否（PTQ +0.9% 足够） |

**止损原则**：任一步骤 FAIL，立即停，回到该技术点假设重新分析，不强行推进。

## 6. 与公理库约束对拍

| 公理 | 融合框架如何满足 |
|---|---|
| SHS-3 连续可还原律 | 结构与量化变换走 λ 平滑过渡，禁止硬切（经典范式主干本身不受影响） |
| SHS-2 叠加不矛盾律 | 过渡态 `(1-λ)·A ⊕ λ·B` 同时携带稠密/稀疏两套信息，不强制二选一 |
| SHS-T 万能扩展模板 | 每个技术点都是「经典基态 → 新基态」的 λ 实例 |
| 经典范式兼容性 | 主干 = 纯 CE + AdamW + 全量训练，λ 只叠加不替代，不脱离经典范式 |
| 实测胜于推论 | 每个技术点强制最小验证实验，硬数据 pass/fail |
| 位级一致性 | λ_q 量化感知确保 q4 权重确定性，MCU 侧可复现 |
| 带宽受限 | λ_s 稀疏化目标是「每 token 只读 top-k 专家」，减少带宽 |
